What is streaming here?
TileRequest input→RenderTiles
interleaving parallel activity→TileResult output

The browser admits up to four tiles via sendAsStream=true. RenderTiles interleaves partitions with a concurrency limit of four. Each partition runs CalculateJuliaTile on the server and routes its result to a reentrant CompressJuliaTile action in the root scope, then to the output pin for SSE delivery. Tiles use gzip when it reduces their size; the browser decompresses them losslessly. All 24 tiles use one c; the browser assembles them offscreen and presents only a complete frame.

Each rendered frame moves 35% toward the latest settled target, snapping exactly within a complex-plane distance of 0.002. Slow frames do not cause wall-clock jumps. Reduced-motion preference skips easing. No future frames are queued. Detail changes are ordinary configuration events and discard unfinished images; palettes recolor only the displayed image locally. SSE is future-only: a lost connection requires a fresh session.
